PeachPal are talking about other fruits and because the response was requested in spanish, it bypasses the regex in both the output and input. 
The same thing works also for the prompt injection model, because it is language specific. 


This is a clear loophole in our layered defence approach of PeachPal!

We need to make sure that the response from the model AND the prompt from the users are in english.

== The Reality of Language detection

**TL;DR** Language is a complicated topic and a living subject.


Many of the different obfuscation attacks can be blocked by a well tweaked language detector, since obfuscation creates a deviation from the pattern of the chosen language. 
More subtle obfuscation attacks could still theoretically pass and would be something you validate. 

Another part is revolving around the nature of language, and the fact that many languages are closely related. They can be grouped in language families, such as germanic and roman.  
Some words can be spelled the same but mean different things in different languages. Here, regex would be too crude since it does not know which word is good or bad. 

Users can also mix languages in the same sentence, since words are borrowed from different languages. For example, the english vocabulary uses many french words. 

Furthermore, language is a living topic that evolves. Words disapper and new words get adopted with time and it's not impossible that language detectors have to be tweaked as time progresses.
